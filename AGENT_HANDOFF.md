# **AGENT_HANDOFF.md**

# **Signal - Agent Handoff Protocol**

**Version:** 1.0

**Status:** Frozen

**Purpose**

This document defines the operational protocol for all agent execution.

It does **not** define architecture.

It does **not** define implementation.

It defines how Builder Agents, Reviewer Agents, and Humans cooperate during development.

Execution order is controlled by:

- CURRENT_PHASE.md
- TASKS.md
- CURSOR_RULES.md
- BUILD_SPEC.md

# **1\. Agent Roles**

## **Builder Agent**

Primary responsibility:

Implement the currently active task.

Builder Agent may:

- Read all project documentation.
- Implement code.
- Create files listed in TASKS.md.
- Modify files listed in CURRENT_PHASE.md.
- Run local validation.
- Run unit tests.
- Produce implementation summaries.

Builder Agent must NOT:

- Redesign architecture.
- Change PRD.
- Change Architecture.
- Change Decisions.
- Modify frozen documents.
- Skip dependencies.
- Skip validation.
- Mark Tier 2 tasks DONE.
- Mark Human tasks DONE.

## **Reviewer Agent**

Primary responsibility:

Verify implementation.

Reviewer Agent performs:

- Code review
- Architecture compliance
- BUILD_SPEC compliance
- TASKS compliance
- Acceptance Criteria verification
- EVAL verification
- Dependency verification

Reviewer Agent never writes production code unless explicitly instructed.

## **Human**

Human responsibilities:

- Tier 2 validation
- Tier 3 execution
- Architecture decisions
- ADR approval
- API keys
- Infrastructure
- Deployment
- CURRENT_PHASE updates

# **2\. Execution Lifecycle**

Every execution session follows the same sequence.

CURRENT_PHASE.md  
<br/>↓  
<br/>TASKS.md  
<br/>↓  
<br/>Identify active task  
<br/>↓  
<br/>Check dependencies  
<br/>↓  
<br/>Read BUILD_SPEC section  
<br/>↓  
<br/>Implement  
<br/>↓  
<br/>Validate  
<br/>↓  
<br/>Reviewer Check  
<br/>↓  
<br/>Human Validation (Tier 2 only)  
<br/>↓  
<br/>Mark DONE  
<br/>↓  
<br/>Update CURRENT_PHASE.md

This order must never change.

# **3\. Session Start Checklist**

Builder Agent must verify:

- CURRENT_PHASE.md exists.
- Active task exists.
- Dependencies complete.
- Files In Scope defined.
- BUILD_SPEC reference available.
- Acceptance Criteria present.

If any item is missing:

STOP.

Request human input.

# **4\. Builder Agent Workflow**

For every task:

Step 1

Read CURRENT_PHASE.md

Step 2

Locate active task.

Step 3

Verify dependencies.

Step 4

Read BUILD_SPEC implementation section.

Step 5

Implement only that task.

Step 6

Run validation.

Step 7

Produce completion report.

Never begin another task automatically.

# **5\. Reviewer Workflow**

Reviewer verifies:

Architecture

↓

Files Modified

↓

Acceptance Criteria

↓

Evaluation Gates

↓

Regression

↓

Dependency Graph

↓

Documentation

↓

PASS / FAIL

If FAIL:

Return findings.

Do not modify architecture.

# **6\. Human Validation Workflow**

Required only for:

Tier 2 tasks

Human verifies:

Evaluation datasets

↓

Quality thresholds

↓

Architecture preserved

↓

Output quality acceptable

↓

Approve

or

Reject

Only after approval may the task become DONE.

# **7\. Handoff Package**

When Builder Agent completes a task it must return exactly:

## **Completed Task**

Task ID

Task Name

## **Files Modified**

List every modified file.

## **Validation**

Tests executed

Results

## **Acceptance Criteria**

Checklist

PASS / FAIL

## **Remaining Work**

Any incomplete items.

## **Recommended Next Task**

Task ID only.

No implementation.

# **8\. Stop Conditions**

Builder Agent must immediately stop if:

- CURRENT_PHASE missing.
- Dependency incomplete.
- Required file missing.
- Acceptance Criteria unclear.
- BUILD_SPEC conflict discovered.
- Architecture conflict discovered.
- New feature requested.
- Required file outside Files In Scope.
- Tier 2 validation reached.
- Human action required.

Builder Agent must never guess.

# **9\. Escalation Rules**

Escalate to Human when:

Architecture change needed

↓

Decision document required

↓

API unavailable

↓

Secrets required

↓

Infrastructure required

↓

Acceptance Criteria impossible

↓

Conflicting documentation

Do not continue until resolved.

# **10\. File Ownership**

## **Frozen Documents**

Builder Agent may read only.

- PRD.md
- ARCHITECTURE.md
- DECISIONS.md
- BUILD_SPEC.md
- CURSOR_RULES.md
- EVAL.md
- AGENT_HANDOFF.md

## **Mutable Documents**

Builder Agent may update task status fields and current slice state only.

- CURRENT_PHASE.md - primary execution tracking file. Regenerated by human at each slice boundary.
- TASKS.md - agents may update task Status field only (TODO → IN PROGRESS → DONE). Task definitions, acceptance criteria, and dependencies are frozen. Aligns with CURSOR_RULES.md Section 25.

## **Source Code**

Builder Agent may modify only files listed in:

CURRENT_PHASE.md

Files In Scope

# **11\. Definition of Complete**

A task is COMPLETE only when:

✓ Dependencies satisfied

✓ Code implemented

✓ Acceptance Criteria PASS

✓ Required tests PASS

✓ Evaluation PASS

✓ Reviewer PASS

✓ Human PASS (Tier 2 only)

✓ CURRENT_PHASE updated

Until every requirement passes:

Status remains

IN PROGRESS

# **12\. Communication Rules**

Builder Agent responses should always include:

- Summary
- Files Changed
- Validation Results
- Acceptance Criteria Status
- Remaining Risks
- Next Recommended Task

Do not include unnecessary explanations.

Be concise.

# **13\. Project Principles**

Always follow:

DECISIONS.md

before

Architecture

before

BUILD_SPEC

before

TASKS

before

CURRENT_PHASE execution.

Never optimize by violating architecture.

Never introduce undocumented behavior.

Never skip deterministic validation.

Prefer deterministic logic before LLM reasoning.

Prefer cheap computation before expensive computation.

Prefer explicit failure over silent recovery.

# **14\. Version Control**

Each completed task should produce a single logical Git commit.

Recommended format:

type(scope): summary  
<br/>Examples:  
<br/>feat(search): implement Tavily research node  
<br/>feat(dedup): add deterministic hybrid dedup  
<br/>refactor(graph): wire Phase 1 pipeline  
<br/>test(entity): add entity extraction validation

Do not combine unrelated tasks into a single commit.

# **15\. Execution Completion**

When every task in the active slice is complete:

- Verify Slice Exit Criteria.
- Update CURRENT_PHASE.md.
- Activate the next slice.
- Begin the next execution cycle.

Execution always advances one slice at a time.

Never skip slices.

Never execute future-phase tasks early.

# **Freeze Status**

This document is operational protocol.

It remains frozen throughout implementation.

Only CURRENT_PHASE.md changes during development.

Any change to this protocol requires a new Architecture Decision Record (ADR) in DECISIONS.md before modification.
